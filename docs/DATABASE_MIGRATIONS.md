# Database Migrations (Drizzle ORM / Drizzle Kit)

Each service owns `src/infrastructure/db/schema.ts` (Drizzle `pgSchema('<name>')` tables), a `drizzle.config.ts`, and a
`migrations/` folder. SQL is generated by Drizzle Kit, reviewed, committed, and applied by our runner.

## Workflow

```bash
cd apps/backend/services/identity-service
npx drizzle-kit generate --name=add_users          # schema.ts diff → migrations/000N_add_users.sql
# review the SQL, then commit it together with schema.ts
npm run db:migrate                                  # from the repo root: applies every service as <name>_migrator
```

For hand-written SQL (RLS policies, triggers, grants): `npx drizzle-kit generate --custom --name=<what>`.
The shared `0000_common_tables.sql` is generated from code — do not edit it by hand:
`npx tsx scripts/gen-common-migration.ts`.

Drizzle Kit's `drizzle.config.ts` reads `<NAME>_MIGRATION_URL` (the **migrator** role URL) for `generate`/`studio`;
it is never used at runtime.

## How migrations are applied

`runServiceMigrations` (`packages/database-utils/src/migrate.ts`):

- reuses Drizzle's migration-file reader, but applies SQL itself — Drizzle's built-in `migrate()` executes
  `CREATE SCHEMA IF NOT EXISTS`, which needs database-level CREATE; migrator roles intentionally do not have it
  (found by the integration tests);
- keeps its bookkeeping table in the service's own schema (`<schema>.__migrations`);
- takes a per-schema advisory lock, so concurrent deploys cannot double-apply;
- runs each migration in its own transaction and rolls back on error;
- is idempotent: running `db:migrate` twice applies nothing the second time (verified).

## Rules

- Migrations are forward-only and additive by default; destructive changes need an expand/contract plan.
- A migration touches **only its own schema**. Cross-service data moves through events or the API, never FKs.
- Every tenant-scoped table gets RLS enabled **and forced**, with policies in the same migration.
- Never edit a migration that has been applied anywhere; add a new one.
